# Reproducible synthetic demonstration

Start the local app with `python scripts/dev.py`. Use only the reserved-domain samples provided. Do not browse those submitted domains; the backend does not fetch them.

1. Open Check, choose the synthetic OTP example and run it. Explain the rule evidence and the conspicuous synthetic indicator label. This is not live threat intelligence.
2. Run the unknown-link example. The result must say unknown/not verified, never safe.
3. With the OTP example restored, export a review summary. It is a derived summary, not an official complaint or forensic original.
4. Open the report form, review separate consent and submit. Save the private receipt locally; it contains the withdrawal capability and must not be committed or shown publicly.
5. Open Analyst using the locally generated analyst key. Review relevance. Explain that acceptance is not guilt and that associations are qualified observations.
6. For a populated Pulse demonstration, run `scripts/seed_demo.py` against a clean separate local database before the session. It inserts six explicitly synthetic reviewed reports. Select the synthetic dataset; the real dataset must not acquire those counts.
7. Show the capability manifest or project studio. State clearly that external reputation, screenshot text extraction, complete KHQR validation and production identity are planned.
8. End with a measured pilot outcome only when it exists. Otherwise show the evaluation protocol and request a design partner.

Do not expose keys in a screen recording. Keep the recording on a synthetic database. Test the demo recovery path and retain a screenshot/video backup with the same limitations visible.
